## Ограничения интеграции 3D

1. `ui/scene.py:build_scene_payload` принимает один результат и всегда ставит
   `id="baseline"` и подпись «Исходное состояние». Сценарий A без доработки
   получит неверную подпись, хотя числа будут из переданного расчёта.
2. `frontend/src/main.js` читает только `data.states[0]`, не проверяет версию
   схемы, не поддерживает переключение A/B и diff_only. Это объём V1/V2.
3. Снятие выбора (`district_id=None`) не представлено в UI и не различается
   Python-валидатором события с некорректным событием. Требуется реализация C0.
4. JS отправляет render_error и показывает локальный fallback; app.py пока
   не использует код ошибки для собственного сообщения, предусмотренного API.
5. Изменение черновика не должно менять сохранённые A/B и числа сцены.

Эти ограничения не мешают baseline-прототипу, но блокируют полную приёмку V1/V2.
Расчёты остаются в Python engine; география и здания условные.
