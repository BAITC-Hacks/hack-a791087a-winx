# Демонстрация: сценарий города и сравнение планов

Основной путь для жюри — подключить собственный OpenAI API token по инструкции в [README.md](../README.md), оставить `DEMO_MODE=auto` и запустить приложение. Кнопки «Показать объяснение результата» и «Подобрать вариант B для плана A» обращаются к API; выбор района, показателей и просмотр 3D-сцены API не вызывают. Если ключ или модель не заданы, интерфейс сообщает о локальном режиме; при ошибке API показывает предупреждение и использует локальный результат. Для прохода без личного API-доступа установите `DEMO_MODE=1` до запуска: ключ не нужен, шаги ниже выполняются локально. Эталон B совпадает с указанными числами именно в demo-режиме; live-предложение может отличаться, но движок проверит его правила и числа.

## 1. Рассчитать исходный пример

Исходное состояние на главной странице: бюджет **100 условных единиц** на пять мер, базовый общий балл Score **52.5577** (чем выше, тем лучше по формуле модели), **Ncrit = 2**. Ncrit считает пары «район/показатель» ниже порога 40.

1. Нажмите «Подставить пример из задания». Это заполняет черновик, но не запускает расчёт.
2. Проверьте пять решений: M7 / Нура, M8 / Нура, M10 / Нура, M12 / весь город, M5 / Сарыарка.
3. Нажмите «Рассчитать и сохранить план A».

Ожидаемый результат основного сохранённого плана A: стоимость **95**, остаток **5**, Score **56.5431** (56.54307 до форматирования), Ncrit **0**. В таблице результатов показаны изменения «до → после», в том числе в Нуре S1 **38 → 48** и S2 **35 → 43.75**. В `DEMO_MODE=1` нажатие «Показать объяснение результата» показывает локальное объяснение; в `auto` при наличии настроек оно запросит ответ OpenAI.

## 2. Проверить OpenAI-функции

При `DEMO_MODE=auto` и заданных ключе и модели после расчёта A нажмите «Показать объяснение результата». Затем оставьте максимум замен равным 1, не закрепляйте решения и нажмите «Подобрать вариант B для плана A». OpenAI предложит альтернативу, а расчётный движок проверит её по правилам и пересчитает показатели. Состав B и его числовые значения зависят от ответа модели, поэтому точный пример из следующего раздела не относится к live-режиму. Если API недоступен или вернул ошибку, интерфейс предупреждает о сбое и показывает локальный результат.

## 3. Найти и сравнить точную demo-альтернативу B

Чтобы получить приведённые далее ожидаемые числа без личного API-доступа, установите `DEMO_MODE=1` до запуска приложения. Если до этого приложение работало с `auto`, остановите его и запустите заново после смены режима, затем заново рассчитайте A. Оставьте максимум замен равным **1**, не закрепляйте решения и нажмите «Подобрать вариант B для плана A». B — альтернатива, которая не заменит A до отдельного принятия. Локальный поиск за одну ревизию проверит до 20 уникальных кандидатов, включая отклонённые по правилам. OpenAI не используется.

В demo-режиме ожидаемый вариант B меняет M5 / Сарыарка на M11 / Нура. Его стоимость — **80**, остаток — **20**, Score — **56.6906** (56.69056 до форматирования), Ncrit — **0**. Прирост к A: примерно **+0.14749**. Это лучший вариант из проверенных кандидатов; полный перебор и доказательство глобального оптимума не выполнялись. В режиме `auto` OpenAI может предложить другой вариант, поэтому эти точные числа для live-режима не гарантируются.

В сравнении отображаются и изменения в худшую сторону: Сарыарка E2 **48.75 → 40**, Сарыарка C1 **47.5 → 45**, Нура T1 **55 → 53.25**. Например, план улучшает итоговый Score, но ухудшение отдельных показателей остаётся видимым.

## 4. Посмотреть результат в 3D

1. В секции «Посмотрите на город» выберите сохранённый план A или предложение B.
2. Выберите направление «Транспорт» и показатель T1.
3. Включите «Только различия A/B по выбранному показателю».

Для Нуры должны отображаться T1 **55** в A и **53.25** в B, разница **−1.75**. Переключение состояния сохраняет выбранный ракурс. В таблице под сценой доступны значения всех пяти районов; при недоступном WebGL можно продолжить сравнение по таблице. Макет не показывает реальную географию или проектируемые здания.

## 5. Проверить защиту сохранённого результата

Измените в черновике M7 на M3. Стоимость M3 на 6 единиц выше M7, поэтому сумма станет **101**. Интерфейс сообщит о превышении бюджета; невалидный выбор не получает расчёт и Score. План A и рассчитанный B остаются сохранёнными, а макет продолжает показывать снимок сохранённого плана. Верните официальный пример, чтобы продолжить.

Можно проверить и ручную альтернативу: нажмите «Рассчитать текущий выбор как B» при неизменённом примере. B будет совпадать с A, а различия исчезнут. Действие «Удалить B и оставить A» удаляет B. После нового запуска ревизии действие «Сделать B новым планом A» переносит B в A и в черновик. Принятие выполняется явно.

Если установить максимум замен в **0**, альтернативы не проверяются и улучшение не заявляется: приложение сообщает «Среди проверенных вариантов подходящего улучшения нет». При изменении ограничений прежняя проверка и B сбрасываются.

## Проверка из терминала

```sh
python run.py --check
```

Команда устанавливает зафиксированные Python-зависимости при необходимости и запускает offline-набор проверок. Она включает demo-режим, удаляет ключ из окружения проверок и не вызывает платный API. Для пересборки 3D-компонента отдельно нужны Node.js и команды из [README компонента](../components/city3d/README.md); готовая сборка уже находится в проекте и для обычного запуска не требуется.
