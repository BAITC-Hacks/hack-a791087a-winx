# Подключение существующего OpenAI API-ключа

В проекте уже есть серверный адаптер `citysim/ai.py`: Responses API объясняет
рассчитанные показатели. Нужны ключ и ID модели, доступной именно вашему API-проекту.
Наличие заявленного баланса $50 само по себе не подтверждает доступ к любой модели.
Ключи, баланс и live-ответ в этой сессии не проверялись реальным запросом.

## Локальный запуск без сохранения ключа

Рабочий каталог расположен в OneDrive. Поэтому рекомендуем ввод ключа в терминале,
без `.env` в синхронизируемой папке. Сначала установить зависимости без ключа:

```sh
python run.py --check
```

Затем в обычном интерактивном терминале из корня репозитория:

```sh
python scripts/start_live.py
```

1. Ввести ID доступной модели Responses API — это не секрет. Его можно также
   передать параметром `--model` или переменной `OPENAI_MODEL`.
2. Вставить существующий API-ключ в отдельный скрытый запрос терминала. Символы
   не отображаются; значение не добавляется в командную строку или файлы проекта.
3. Открыть локальное приложение. Нажать кнопку объяснения, чтобы выполнить
   один настоящий запрос. До нажатия платный API не вызывается.
4. При успехе интерфейс показывает `Режим объяснения: openai`; при ошибке —
   demo с предупреждением. Demo не является подтверждением рабочего подключения.
5. После завершения остановить сервер Ctrl+C. При следующем запуске ключ вводится снова.

Launcher передаёт ключ только в окружении дочернего Python-процесса. Родительское
окружение не изменяется. Он не сохраняет ключ на диск, не записывает его в Git и
не передаёт в URL/JavaScript/3D. Ключ нужен серверу в памяти во время работы;
это не защита от администратора или вредоносного ПО на самом компьютере.
Ввод через перенаправленный stdin и небезопасный echo-fallback getpass запрещены.

Аргументы `--port 8502` и `--headless` поддерживаются. Скрипт не меняет ExecutionPolicy
PowerShell и не требует установки дополнительных библиотек.

## Если ключ уже хранится в защищённом окружении

Приложение принимает `OPENAI_API_KEY`, `OPENAI_MODEL`, `DEMO_MODE=0` из окружения
серверного процесса; настройки процесса приоритетнее `.env`. Обычный `python run.py`
использует их. Значение ключа не нужно указывать в аргументах команды.

Вне синхронизируемых папок допускается локальный `.env`, исключённый из Git.
Не сохранять ключ в `.env.example`, README, Python/JS-код, браузерный storage или чат.
`.gitignore` предотвращает обычное добавление файла в Git, но не шифрует его и не
останавливает OneDrive. Не отправлять приватные ключи напарнику сообщением в репозитории.
Для серверного размещения использовать переменные сервиса/хранилище секретов хостинга.
Рекомендация хранить API-ключи в окружении или secret manager соответствует
[OpenAI production guidance](https://developers.openai.com/api/docs/guides/production-best-practices).

## Расходы и доступ

- Использовать существующий ключ нужного OpenAI-проекта; не требуется выдавать
  приложению административные полномочия. Для команды предпочтительны отдельные
  проектные ключи с нужными правами, а не распространение одного личного ключа.
- Для первых проверок предлагается отдельный лимит $10 и уведомление на $5;
  это рекомендация, настройки аккаунта автоматически не изменялись.
- В OpenAI Platform → Project → Limits различать уведомления и **Enforce a hard limit**:
  уведомление само не прекращает запросы. Hard limit прекращает затронутые запросы,
  но применяется с задержкой, поэтому возможен небольшой перерасход. Не считать
  баланс $50 точным мгновенным ограничителем. [Официальные правила лимитов](https://developers.openai.com/api/docs/guides/spend-limits).
- Текущий адаптер ограничивает ответ 700 output-токенами, timeout 15 секунд,
  повторы отключены. Это не общий денежный лимит: повторные нажатия оплачиваются отдельно.
  Тарификация зависит от выбранной модели и входного/выходного объёма.
- Перед публикацией приложения добавить серверные ограничения частоты запросов
  и доступа к платным действиям. Ключ должен оставаться на Python-стороне.

## SSH

OpenAI API-ключ и SSH-ключ решают разные задачи. Для вызовов OpenAI SSH не требуется.
Если позднее понадобится сервер, достаточно сообщить его адрес, пользователя, порт
и локальный путь к приватному SSH-ключу; содержимое приватного ключа в чат не передавать.
Размещение на сервере в этом шаге не выполнялось.

## Проверка подготовки

`python run.py --check` включает offline-тесты launcher: отсутствие ключа в аргументах,
выводе и новых файлах; сохранность родительского окружения; отказ при пустом ключе,
неинтерактивном или небезопасном вводе. Тесты используют фиктивное значение и не делают
реальных API-вызовов. Успешный платный запрос подтверждается отдельно через интерфейс.

На Windows/Python 3.12 проверены скрытый ввод и HTTP200 на фиктивном ключе.
После обнаруженного зависания Ctrl+C добавлены опрос процесса и ограниченное ожидание
завершения его дерева. Соответствующие offline-тесты проходят; повторная интерактивная
проверка остановки после исправления была прервана и остаётся отдельным пунктом проверки.
