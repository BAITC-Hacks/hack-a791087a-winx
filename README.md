# Аким на 5 часов — winx

## Описание и назначение

AI-симулятор решений городского управленца: одинаковый бюджет **100**, пять районов,
каталог из 14 мер, горизонт восемь кварталов. Целевой сценарий: выбрать ровно пять мер,
проверить правила, получить Astana Quality of Life Score и понятное объяснение компромиссов

**Текущий статус: U1/I1/A1 готовы — выбор, расчёт, сохранение и объяснение плана A.**
Пять решений проходят проверку движком E1/E2. Паспорт показывает расходы, Score,
показатели до/после и трассировку. Изменение черновика сохраняет прежний результат
с предупреждением; новое объяснение запускается отдельной кнопкой.
3D пока показывает исходный город. Сценарии в 3D, A/B и ревизор — следующие этапы.
[План и владельцы](docs/PLAN.md), [контракт](docs/API.md).

Независимая [проверка P0](docs/REVIEW.md): 8 тестов и запуск подтверждены также на
Windows/Python 3.12.0. [Уточнённая идея](docs/IDEA.md) описывает паспорт сценария,
сравнение до/после и проверяемого советника; советник ещё не подключён.

Целевой продукт — веб-приложение с 3D-сравнением будущих состояний. Текущий
[3D-прототип](components/city3d/README.md) — подготовительная часть V1;
полная интеграция сценариев V1/V2 и ревизор остаются в плане.

## Архитектура

```text
UI (выбор) → engine (правила → эффекты/лаги/синергии → Score)
                                    ↓ готовый SimulationResult
                              ai (объяснение) → UI (результат)
```

Движок — чистые функции без сети, UI и env. LLM не рассчитывает показатели,
бюджет или Score. Невалидный набор не получает Score. Все числовые данные интерфейс
берёт из engine. Форма вызывает `validate_scenario` и `simulate`; сохранённый
результат отделён от редактируемого черновика. JS получает baseline и не считает Score.

```text

citysim/ai.py          # @AaaDddmyrza: объяснение и offline fallback
```

## Технологии

Python 3.11+, Streamlit, официальный OpenAI Python SDK (Responses API), python-dotenv.
Черновик, план A и объяснение хранятся в сессии Streamlit; после перезагрузки
страницы или перезапуска сервера сохранение не гарантируется. Постоянного хранилища пока нет. Без Docker, базы данных и облачного сервера.

## Установка

Нужны Python **3.11+** с pip/venv и Git. Проверено на Windows с Python 3.14.4.
При первой установке нужен интернет для скачивания зависимостей; для demo после
установки аккаунты, ключи и подписки не нужны. Linux может требовать пакет python3-venv.

```sh
git clone https://github.com/BAITC-Hacks/hack-a791087a-winx.git
cd hack-a791087a-winx
```

Репозиторий выдан организаторами и приватный: права нужны только для получения исходников.
После получения архива/клона приложению авторизация в GitHub не нужна.

## Запуск

Из корня проекта, одна команда (Windows / macOS / Linux):

```sh
python run.py
```

Если интерпретатор называется `python3`, используйте `python3 run.py`.
Команда сама создаёт `.venv`, устанавливает версии из `requirements.txt` и запускает
Streamlit. Активация окружения и создание `.env` для demo не требуются.
Откройте [локальное приложение](http://127.0.0.1:8501). Остановка — Ctrl+C.
Сервис слушает только 127.0.0.1. При занятом порте: `python run.py --port 8502`.
Без открытия браузера: `python run.py --headless`.

## Переменные окружения

Для безопасной локальной настройки live-режима см. [руководство по секретам](docs/SECRETS.md). Опциональный запуск с маскированным вводом ключа без сохранения в файлы: `python scripts/start_live.py` (интерактивный терминал; модель можно передать как `--model MODEL_ID`). Ключ доступен только запущенному приложению; платный запрос выполняется после действия пользователя в интерфейсе.

При обычном запуске вне синхронизируемых папок можно скопировать `.env.example` в `.env` и отредактировать. Настройки окружения процесса приоритетнее `.env`; `.env` и секреты исключены из Git. Git ignore не защищает файл от загрузки в OneDrive.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DEMO_MODE` | `1` | `1` гарантирует шаблон без вызова OpenAI, даже если есть ключ |
| `OPENAI_API_KEY` | пусто | Ключ нужен только для live; без ключа автоматический demo |
| `OPENAI_MODEL` | пусто | Доступная вашему API-проекту модель Responses API; без неё demo |

Для live укажите все три: `DEMO_MODE=0`, ключ и модель. Live-запрос выполняется только
по нажатию кнопки объяснения. Ошибка/таймаут/пустой ответ → demo с предупреждением.
Личный ключ не требуется для проверки проекта; платный API не вызывается проверками.
Реальный live-доступ не проверен; успешный ответ, ошибка и пустой ответ покрыты моками. Используется
[официальный Responses API](https://developers.openai.com/api/docs/libraries).

## Проверка основного сценария

1. Запустите `python run.py` без `.env` и ключа: бюджет **100**, базовый Score **52.5577**, Ncrit **2**.
2. Нажмите «Заполнить пример из задания»: M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка.
3. Нажмите «Рассчитать и сохранить A»: стоимость **95**, остаток **5**, Score **56.5431**, Ncrit **0**.
4. Изучите паспорт: Нура S1 **38 → 48**, S2 **35 → 43.75**; раскройте показатели и эффекты.
5. Нажмите «Объяснить сохранённый план A»: объяснение в режиме demo, без сети.
6. В первом слоте замените M7 на M3: стоимость **101**, ошибка бюджета. Попытка расчёта
   сохраняет прежний A и его объяснение с явным предупреждением об изменённом черновике.
7. Верните пример, измените район M7 на Есиль и рассчитайте: A обновится; прежнее объяснение очистится.
8. Ниже находится исходный город в 3D. Выбор района/показателя не меняет сохранённый план.

Автоматическая проверка с установкой зависимостей, без ключа:

```sh
python run.py --check
```

Проверены **89 Python-тестов**: движок, контракты, сохранение снимков, паспорт,
AI/fallback и сценарии формы через AppTest. JS-компонент: `npm test` в
`components/city3d/frontend` — 4 теста. Реальный Chromium: расчёт эталона,
отклонение бюджета 101, сохранность A, demo-объяснение и форма при ширине 390 px.
AppTest сам по себе не доказывает рендеринг WebGL; браузерная проверка 3D описана
в [README компонента](components/city3d/README.md).

## Правила и ограничения

Источники истины: [TASK.md](docs/TASK.md) и [DATASET.md](docs/DATASET.md), без изменений.
Пять решений допускают максимум две меры одного направления; покрытие всех пяти
направлений не обязательно. Городские меры не принимают район.
Формула: `Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit`.
Штрафуется каждая пара район/показатель строго ниже 40; промежуточные числа не округляются.
Синтетическая модель показывает последствия в рамках датасета, а не прогноз реального города.
