# Город в 3D — V1

Запуск из корня проекта: `python run.py`. Node.js для обычного запуска не нужен:
готовые `build/city3d.js`, `build/city3d.css` и лицензия входят в комплект.
Переключатель выбирает исходный город или сохранённый план A. API-ключ и платные
запросы для 3D не нужны. Черновик не подменяет рассчитанный снимок.

## Проверка вручную

1. Исходное состояние, S1: Нура — 38, S2 — 35, районный балл 49.1800.
2. Заполнить официальный пример и рассчитать: автоматически выбран A;
   в Нуре S1=48, S2=43.75, районный балл 52.9625. Score города 56.5431.
3. Изменить черновик без расчёта: A в сцене остаётся прежним. Переключить baseline/A:
   меняются подпись и значения, но сохраняются камера и выбранный район.
4. Выбрать район кнопкой или объектом; подпись Streamlit под сценой подтверждает
   ответ Python. «Все районы» снимает выбор и показывает пять значений показателя.
5. Повернуть/приблизить сцену и сменить показатель. «Сверху» и «Общий вид» задают
   явные положения, +/− меняют масштаб. На узком экране карточка идёт под макетом.
6. «Показатели сцены — таблица» всегда содержит пять районов текущего снимка.
   При ошибке WebGL таблица раскрывается, выбор района и карточка остаются доступны.
   «Повторить 3D» заново создаёт renderer; успешный запуск очищает сообщение об ошибке.

Макет условный: положение районов, количество и высота зданий не являются данными.
Только столбцы отражают показатель по общей шкале 0–100; риска — порог 40.
Оранжевый столбец обозначает <40; точные числа подписаны текстом, включая дробные.
Вид не показывает реальную географию, прогноз строительства или квартальную динамику.

## Разработка

Из `components/city3d/frontend`:

```sh
npm ci
npm test
npm run build
```

Node.js 24; Three.js 0.186.0 и Vite 8.3.0. Three.js/OrbitControls включены в bundle,
CDN-импортов нет. После изменения JS/CSS пересобрать компонент и перезагрузить
страницу; при старой сборке в сессии перезапустить Streamlit.
`frontend/node_modules` исключён из Git; `build` сохраняется в Git.

`ui/scene.py` копирует SimulationResult в ScenePayload v1 и нормализует события.
`__init__.py` возвращает SceneEvents, включая `district_id: null` и известные коды
ошибок. `protocol.js` проверяет версию и значения до создания WebGL; `main.js`
владеет DOM/fallback, `scene.js` — WebGL/камерой, `lifecycle.js` — очисткой.
Renderer работает по событиям без бесконечного animation loop. При удалении
освобождаются геометрия, материалы, renderer, observer и обработчики; это относится
и к частичной инициализации. Камера хранится по стабильному ключу компонента.

Python передаёт один выбранный снимок baseline или A, что разрешено C0 для V1.
Builder также проверяет форму A/B для следующего этапа; UI A/B и diff_only — V2.
Движок, общий API, датасет и серверная часть ревизора этим пакетом не меняются.

## Проверено — 23 сентября 2026

- 155 Python-тестов и 11 JS-тестов; Vite build.
- Streamlit в Chromium: настоящий WebGL, эталон A, baseline/A с S1/S2,
  снятие/возврат выбора с ответом Python и неизменная камера после переключения.
- AppTest: изменение черновика не меняет сцену A; событие context_lost сохраняет
  A и доступную таблицу с Нура=48. Моки не заменяют браузерную проверку ниже.
- Изолированный стенд итогового bundle: реальный WEBGL_lose_context, отказ getContext,
  неизвестная schema_version и последующее восстановление. Нет дублирующихся canvas.
  CSP разрешает загрузки только с localhost, внешняя сеть заблокирована для стенда.
- Приложение проверено при ширине 760 px; компонент — в iframe шириной 390 px
  (полезная ширина 375 px с полосой прокрутки), без горизонтального переполнения,
  с выбором района и сменой снимка. Физический pinch на телефоне не проверен.

Платные API-вызовы не выполнялись. Постоянное хранение плана после перезагрузки
страницы/сервера пока не реализовано; это ограничение сессии приложения.
